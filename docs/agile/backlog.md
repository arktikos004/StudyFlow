# StudyFlow v2 產品待辦清單

由 Product Owner 維護；Sprint 3 會依這份清單逐條驗收。

**Sprint 目標**
- **Sprint 1（地基）**：
  - 新介面的設計系統上線。
  - 科目可以從整片色盤任意挑色。
  - 所有新功能的資料與 API 一次到位。
- **Sprint 2（功能與頁面）**：每一頁依新設計改版，並補齊目標、計時、任務、月曆、筆記、搜尋、成就等功能。
- **Sprint 3（驗收）**：
  - code review、QA、設計審查。
  - PO 逐條驗收。

## Definition of Done

每個故事都要全部符合才算完成：

- **資料與 API**
  - 輸入驗證用前後端共用的 zod schema；錯誤訊息用 zh-TW。
  - 每個查詢都限定目前使用者，引用的 id 用 `assertOwned` 檢查。
  - 日曆日期存 `YYYY-MM-DD`，時間點存 UTC 毫秒；畫面上的時間依 `user.timezone` 顯示。
- **介面**
  - 符合 `DESIGN.md`：只用 token、文字對比 ≥ 4.5:1、觸控目標 ≥ 44px、可用鍵盤操作、支援 reduced motion。
  - 淺色、深色、手機寬度都檢查過。
- **測試與檢查**
  - 新 API 有整合測試，包含跨使用者隔離：別人的資料回 404，引用別人的 id 回 400。
  - `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 全部通過。
  - migration 只新增欄位與表，並通過審查用的 grep（見 `.claude/agents/backend-engineer.md`）。
- **流程**：經過 code review，由 Scrum Master 合併進 `develop`。

- 解鎖時間只在經過 API 的寫入時記錄：直接改資料庫的資料不會有解鎖時間。

**需要使用者手動驗收**
- 手機實機上傳：iOS Safari 的相機與相簿、HEIC 照片的提示、直拍的照片有沒有轉正。
- 螢幕報讀器會不會念出對話框裡的失敗訊息。
